# Trustible Astryx migration

Trustible is now implemented as a strict Astryx-first interface on Astryx Core 0.4.3. The MVP routes, demo reducer, local persistence, and Cloudflare static-export contract remain unchanged.

## Astryx system

- `app/trustible-theme.ts` extends Astryx Neutral with Trustible blue-grey, warm architectural, status, radius, typography, and motion tokens.
- `app/trustible-theme.css` and `app/trustible.js` are generated by `npm run astryx:build`; `app/trustible.cjs` is the doctor-compatible metadata bridge.
- The root shell uses `TopNav`, `MobileNav`, `TopNavHeading`, `TopNavItem`, `Button`, `Link`, `Card`, `Badge`, and Astryx typography.
- Route controls use `TextInput`, `TextArea`, `Selector`, `ProgressBar`, `EmptyState`, and themed Cards instead of raw form controls.

## Intentional custom layer

Custom CSS is restricted to Trustible-specific composition: the warm architectural hero, contractor cover treatments, inspiration color fields, milestone connector geometry, page grids, and responsive spacing. Interactive semantics and visual primitives come from Astryx.

The single generated asset `public/trustible-architectural-hero.png` is reused by the discovery hero and Open Graph metadata. No third-party image dependency was added.

## UX behavior retained

- Discovery search, budget selection, verified-only filtering, and shortlist persistence.
- Quote request creation and confirmation.
- Project funding, evidence submission, approval, disputes, refunds, completion, and review unlocking.
- Contractor onboarding, dashboard, shared milestone ledger, and public profile preview.

## Validation

- `npx tsc --noEmit` passes.
- `npx astryx doctor` passes with zero warnings or failures.
- `npm run build` passes and exports all 26 static routes.
- Browser QA covers desktop/mobile navigation, discovery, quote submission, project actions, contractor actions, keyboard focus, responsive overflow, and console errors.

## Release

Cloudflare Pages is the canonical public deployment target. The Sites staging build remains supported by `scripts/prepare-sites-dist.mjs` but is not republished by this migration.
